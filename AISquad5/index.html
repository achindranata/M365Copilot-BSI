Section 2

Harness choice at a glance

SNAP and ARGUS are both built in Copilot Studio. The harness is chosen per part of the process, based on the kind of work it does.

Use casePart of the processHarnessWhy
SNAPThe whole flow: SNAP Intake Agent and agent flows AF-01 to AF-06 — intake, confirmation, enrichment, routing, approvals, Nota and SuratStandardA fixed transaction with set fields, fixed rules and approvals: every application must follow the same audited route.
ARGUSAnalysis (steps 1–3): ARGUS Analyst, GAIA Financial Analyst, ATLAS Macro & Policy Analyst, with workflows WF-01 and WF-02 as their toolsGitHub CopilotReasoning-heavy, multi-step work that produces Word and Excel files; skills, memory and a native code interpreter. Billed in Copilot Credits.
ARGUSData sync, monitoring, alerts: agent flows AF-01 to AF-05 and ARGUS SentinelStandardScheduled, unattended runs with deterministic rules (agent flows) and proactive Teams alerts, which the GitHub Copilot harness doesn't support.
Rule of thumb

Use the standard harness for work that must run the same way every time, run on a schedule, write records or push Teams alerts. Use the GitHub Copilot harness for reasoning-heavy, multi-step analysis where the agent plans its own steps and people review the result. GitHub Copilot harness agents use workflows as tools; standard harness agents use agent flows. When a use case needs both harnesses, the two halves meet through a shared Dataverse register.
