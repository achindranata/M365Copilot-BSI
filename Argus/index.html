Understanding of the use case and requirements

Sources: email from M Mochtar Effendy (BSI), “Use Case Argus”, 2 Nov 2026, with ARGUS_Use_Case.pptx (6 slides; AI Squad BSI template, update 22/10/2026). Earlier email of 27 Oct introduced it as use case no. 22.

ARGUS — Description

Project ARGUS — AI Risk Governance & Unified Strategy Platform — is CRR's web-based, AI-powered intelligence platform for corporate financing, built on the idea of “all function in 1 place”. ARGUS acts as the main orchestrator: it coordinates two specialist agents — GAIA for financial analysis (statement extraction, historical analysis and checks, projection and repayment capacity, recommended structure and covenants) and ATLAS for macro, portfolio and policy (macro insight, sector and business-group focus, internal and external rules) — and combines their results into one integrated risk perspective for financing decisions. It covers the corporate financing process from initiation and targeting, through financing evaluation and NAP review, to monitoring, advanced monitoring and collection, drawing on IDEAL, the NAP Database, risk monitoring data and regulations. The aim is to turn data into intelligence, intelligence into anticipation and anticipation into better financing decisions: cutting the analysis cycle from about 40 to about 24 hours while analysts — Corporate Financing Analysts, Relationship Managers and Corporate Analysts in CRR, CB1, CB2 and CB3 — focus on judgment and risk recommendations.

Pain points

  • Long manual process, prone to human error (SLA ± 40 hours), looping 2–3 times with rework, queues and delay.
  • Risk signals from customer performance are hard to detect.
  • Customer data is scattered across many documents and sources.
  • Complex internal and external rules make recommendations hard.
  • Later stages are manual and sequential, across units, with physical documents.

  1. 1Ask + attach — the analyst or RM opens ARGUS Analyst in Teams or Microsoft 365 Copilot, names the customer and facility, and attaches the financial statements (per run, not knowledge).
  2. 2Financial — ARGUS Analyst delegates to GAIA Financial Analyst, a connected agent on the same harness.
  3. 3Tool: LK Extract — GAIA calls the workflow WF-01 · ARGUS LK Extract as a tool. Its process-documents AI action returns the statement figures with a confidence score per field, within the 100-second limit for agent-called workflows.
  4. 4Save LK — WF-01 saves the figures to the ARGUS Register. GAIA then runs its skills — Financial Checker, Projection & Repayment Capacity (builds the Excel workbook) and Structure & Covenant Recommender — computing in code with the native code interpreter.
  5. 5Macro + policy — ARGUS Analyst delegates to ATLAS Macro & Policy Analyst (skills: Macro Insight, Sector & Group Recommender, Policy & Procedure Check).
  6. 6Ground — ATLAS answers from the ARGUS Policy Library in SharePoint. Azure AI Search isn't a supported knowledge source on the GitHub Copilot harness, so the argus-nap-archive index is reached through a tool (MCP server or connector) or the archive moves to SharePoint — verify.
  7. 7Tool: Save — ARGUS Analyst runs its NAP Review skill, combines GAIA and ATLAS into one risk view and, when the analyst confirms, calls the workflow WF-02 · ARGUS Save Analysis.
  8. 8Write — WF-02 writes the recommendation, structure, covenants and NAP findings to the Register, with a version.
  9. 9Recommendation — the analyst receives the recommendation pack: NAP draft with review findings (Word) and the projection workbook (Excel). Files the agent creates are capped at 10 MB each. The analyst validates and gives judgment (± 12 h) before Persetujuan Komite.
  10. 10Internal — the agent flow AF-01 · ARGUS Data Sync loads IDEAL and NAP Database data on a schedule through a connector or on-premises data gateway (verify with DAS).
  11. 11Risk data — AF-01 also loads Risk Monitoring (Alert, FRR) and Financial Dashboard figures.
  12. 12Regs — the agent flow AF-02 · ARGUS Knowledge Refresh loads regulations, macro and industry data into the ARGUS Policy Library and the search index.
  13. 13Load — synced data lands in the ARGUS Register, which both harnesses read.
  14. 14Daily — the agent flows AF-03 · ARGUS Performance Monitor (early-warning rules, risk rating, draft action plan) and AF-04 · ARGUS Covenant Tracker (covenant tests) run every day without a user.
  15. 15Dashboard — results feed the ARGUS Risk Monitoring Dashboard in Power BI.
  16. 16Breach — a breach calls the agent flow AF-05 · ARGUS Alert Dispatch, which posts as ARGUS Sentinel.
  17. 17Alert — the RM gets a proactive Teams card from ARGUS Sentinel with the risk rating and draft action plan, acknowledges it, and can open ARGUS Analyst from the link for a deeper look.

Why this stack

Analysis → agents on the GitHub Copilot harness. Steps 1–3 are reasoning-heavy, multi-step work that produces Word and Excel files: the agent plans its own steps, uses skills, remembers across conversations and runs code natively. The analyst validates every result, so the variability of model-planned steps is acceptable here. GAIA and ATLAS are connected agents because they are separate domains with their own skills — and a GitHub Copilot harness agent can only connect to other GitHub Copilot harness agents.
Tools of those agents → workflows, not agent flows. Microsoft Learn documents workflows (GitHub Copilot harness) as the flow tool for GitHub Copilot harness agents; agent flows are the standard harness's tool type, and calling one from a GitHub Copilot harness agent isn't documented. WF-01 uses the workflow's native process-documents AI action; WF-02 is a fixed write sequence. Both must answer the agent within 100 seconds; adding workflows as tools on these agents is in preview.
Data sync, monitoring and alerts → agent flows on the standard harness. They run on a schedule without a user and must give the same answer for the same data: agent flows are deterministic (same input, same output), live in solutions with versioning for dev/test/prod, and can post proactive Teams messages through ARGUS Sentinel, which the GitHub Copilot harness doesn't support. Workflows would also run on a schedule, but Microsoft Learn notes their results can vary when actions use AI.
How the two halves meet. Through the shared ARGUS Register in Dataverse (both harnesses support Dataverse tables as knowledge) and the link on the alert card — not agent-to-agent, because connected agents don't cross harnesses.

Guardrails

ARGUS prepares; people decide. The analyst validates every recommendation, and financing decisions stay with Persetujuan Komite. Writes to the Register happen only through WF-01, WF-02 and the agent flows, so every change follows a defined path and is logged. Customer financial data stays in BSI's tenant under BSI's access controls. Data access approval, rule ownership and production use of preview features: verify with BSI.

Assumptions and to be verified

  • Preview features: agent creation and workflows as tools on the GitHub Copilot harness are in preview — confirm general availability for the Q1 2027 go-live.
  • Cost: estimate Copilot Credits for ARGUS Analyst, GAIA and ATLAS (build, test and run), and Copilot Studio capacity for WF-01, WF-02 and AF-01 to AF-05 (prepaid or pay-as-you-go); confirm BSI accepts usage-based billing before the pilot.
  • WF-01 time limit: an agent-called workflow must answer within 100 seconds — test with BSI's largest financial statements.
  • Azure AI Search: not a knowledge source on the GitHub Copilot harness — reach argus-nap-archive through a tool (MCP server or connector), or move the archive to SharePoint.
  • Connected agents: hand-offs have a payload limit, so GAIA and ATLAS return compact figures and findings, not whole files.
  • Workflows vs agent flows: calling a standard agent flow from a GitHub Copilot harness agent isn't documented — the design doesn't rely on it; the halves meet through the ARGUS Register.
